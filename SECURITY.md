# Security Policy

## Report a vulnerability

Preferred reporting options (in order):

1. Use GitHub's private Security Advisory for this repository (recommended).
2. Email the maintainer directly at: REPLACE_WITH_MAINTAINER_EMAIL (replace with your contact).

Do NOT open a public issue for security-sensitive information.

## What to include in a report

- A clear description of the vulnerability and its impact.
- Affected component(s) and affected commit(s) or versions (commit SHA when possible).
- Step-by-step reproduction steps and a Proof-of-Concept (PoC) if available.
- Suggested mitigations or fixes, if you have them.
- Your contact information and any embargo preferences for disclosure.

## Triage and response

- Acknowledgement: we aim to acknowledge reports within 48 hours.
- Initial response: maintainer will provide an initial plan or timeline within 14 days.
- Fix timeline: will depend on severity; maintainer will coordinate and communicate progress.

## Disclosure policy

We follow responsible disclosure. Please coordinate with the maintainer before publicly disclosing any confirmed vulnerability. If coordination fails, responsible public disclosure after a reasonable period (typically 14 days after fix availability) is permitted.

## Remediation and patches

- Security fixes should be developed in a branch named `security/<short-desc>` and opened as a PR marked for security review.
- Critical fixes may be backported to supported branches as appropriate.

## Emergency contact and alternatives

If you cannot reach the maintainer by email, open a GitHub Security Advisory and include the details above.

## Optional: PGP key

If you prefer to send sensitive details encrypted, provide your PGP key fingerprint here and the maintainer will publish a key or alternative secure channel.
